
## JetPack / Ubuntu 版本对照（2026-07 核对）

Jetson 设备端跑的是 L4T（Linux for Tegra），Ubuntu 版本跟着 JetPack 走：

| JetPack | L4T | 设备端 Ubuntu | 内核 / CUDA | 备注 |
|---------|-----|--------------|-------------|------|
| 5.x | 35.x | 20.04 | 5.10 | 旧 |
| 6.x | 36.x | **22.04** | 5.15 / CUDA 12 | 生态成熟，「之前的 22.04」|
| **7.0 / 7.2** | 38.2 / 39.2 | **24.04 LTS** | 6.8 / CUDA 13 | 最新，与本项目 24.04 对齐 |

要点：
- JetPack 7.0 最初只面向 Jetson Thor，**JetPack 7.2** 才把 Ubuntu 24.04 / CUDA 13
  扩展到整个 **Jetson Orin** 系列 → Orin NX 现在可刷 24.04，与 openpilot 项目、
  `Dockerfile.openpilot-arm64`（基于 24.04）天然一致。
- SDK Manager 工具最新版（2.4.0）host 已支持 Ubuntu 24.04（x86_64/arm64），
  24.04 开发机可原生跑（早期需 22.04 或 VM，此坑已填）；但「工具支持某 host」≠
  「要装的 JetPack 包也支持该 host」，JetPack 6.x 刷机通常仍要 20.04/22.04 host。

权衡（对本项目）：
- 选 **JetPack 7.2**：设备端 24.04，省去 22.04/24.04 兼容折腾；但 7.2 很新，很多
  第三方生态（PyTorch Jetson wheel、jetson-containers 等）仍停在 JetPack 6，CUDA 12→13
  可能不兼容。openpilot 推理走自带 tinygrad，对 PyTorch wheel 依赖小，但 tinygrad 的
  CUDA/GPU 后端需在 CUDA 13 上验证。
- 选 **JetPack 6.2**（22.04）：生态成熟、先把链路跑通，代价是设备端与项目 24.04 不一致，
  需注意 glibc/依赖差异。
- 来源：NVIDIA JetPack 官方页、JetPack 7.2 发布说明、SDK Manager 系统要求（内容已改写
  以符合许可）。

### 6.x → 7.2 升级路径（跨大版本，2026-07 核对）

**结论：跨大版本不能用 `apt upgrade` 一条命令升。** 区别：
- 同大版本（6.2.1 → 6.2.2）：改 apt 源 + `apt full-upgrade` 可原地升，不用重刷。
- 跨大版本（6 → 7）：内核 5.15→6.8、bootloader/分区布局都变，apt 走不了。

前提（好消息）：JetPack 7.2 要求设备已有 **6.x 代 UEFI/QSPI 固件**；已在 6.x 即满足。
若还停在出厂老固件，需先补 6.x 固件。

三条路径：

| 方式 | 是否需恢复模式 | 是否需 host PC | 说明 / 风险 |
|------|--------------|---------------|------------|
| ① SDK Manager 重刷 | 需 Force Recovery(RCM) | 需（22.04/24.04）| 最常规；**全量重刷，清空设备** |
| ② Jetson ISO USB 安装器 | 否（U 盘启动安装）| 否 | 7.2 新增；主要面向 Orin Nano/AGX devkit，Orin NX 视载板 |
| ③ 镜像式 OTA | 否（原地升）| 否 | 官方称适合跨大版本；非 apt，需备 OTA payload；**有 brick 案例，风险高** |

> Orin NX 是模块，进 RCM 的针脚/按键**取决于载板**（devkit / 第三方 / 自制），需查
> 对应 carrier 手册。恢复模式一般是短接 FC_REC + GND 针脚（或按 Force Recovery 键）再上电。

**推荐**：走 ① SDK Manager 重刷（最干净），当成全新安装；不要在装车的生产设备上做
原地 OTA（③ 有 brick 风险）。

## 开机自启动
sudo nano /etc/systemd/system/openpilot.service


[Unit]
Description=OpenPilot Docker (Jetson)
After=docker.service graphical.target
Requires=docker.service

[Service]
Restart=always
RestartSec=5
TimeoutStartSec=0

# X11 显示（根据你现在的环境）
Environment=DISPLAY=:1
Environment=XDG_RUNTIME_DIR=/tmp/runtime-root

ExecStartPre=/usr/bin/xhost +local:docker

ExecStart=/usr/bin/docker run --rm \
  --name openpilot \
  --network host \
  --ipc host \
  --runtime nvidia \
  --privileged \
  -e DISPLAY=:1 \
  -e XDG_RUNTIME_DIR=/tmp/runtime-root \
  -v /tmp/.X11-unix:/tmp/.X11-unix:rw \
  -v /run/dbus/system_bus_socket:/run/dbus/system_bus_socket \
  -v /etc/machine-id:/etc/machine-id:ro \
  -v /data:/data \
  --device /dev/dri \
  --group-add video \
  mindcont/openpilot-arm64:latest \
  /home/batman/openpilot/selfdrive/ui/ui

ExecStop=/usr/bin/docker stop openpilot

[Install]
WantedBy=graphical.target
