# CAN 数据抓取与解析验证清单

> 目的：在真正接入 openpilot（`card.py`/`carState`）之前，独立验证"能否从真实 CAN
> 总线抓到车道预测所需的目标信号，且信号数值随车辆真实状态正确变化"。这是
> [CAN接入实车任务清单.md](CAN接入实车任务清单.md) 第三部分「Day1」步骤 6/9/10 的
> 详细展开，只用 `cabana`/`panda` + 现有解析脚本，**不需要跑 openpilot**，验证范围
> 更小、风险更低，建议先做完这份再进入完整的 openpilot 集成验证。

## 为什么需要"动态"验证，不只是"静态存在性"验证

已有的 [大众速腾CAN抓包解析报告.md](大众速腾CAN抓包解析报告.md) 是车辆**完全静止、
点火 ON、发动机未启动**时抓的包，验证结论是"车速/方向盘/档位等信号解析出来的数值
合理"（比如方向盘角度解析出 8.9°）。但这只证明了：

- 信号在总线上广播（消息 ID 存在）
- 用 `vw_mqb.dbc` 能解析出一个数值、数值在合理范围内

**没有证明**：解析出的数值真的对应"方向盘转动了 8.9 度"这个物理事实，而不是恰好
命中一个凑巧合理的默认值/其他字段错位。车辆完全静止时，几乎所有信号都不变化，
无法靠"数值变了没有"这个最直接的信号做交叉验证。

本清单的核心方法：**主动制造已知的状态变化（转动方向盘到某个角度、挂入某个挡位、
踩刹车），立即抓包解析，检查对应字段是否按预期方向/幅度变化**。这是比"看数值是否
在合理范围"更强的验证。

## 零、前置准备

- [ ] **0.1 确认 cabana 可用**
  `cd tools/cabana && ls` 确认二进制/脚本存在；或用已编译好的 `cabana` 命令。
  依赖 panda 已插上 Orin NX（或开发机）USB。

- [ ] **0.2 确认 panda 只读**
  跑一次 `python3 tools/vw/check_panda_readonly.py`，确认默认态只读（这一步不涉及
  接车，只是核实硬件默认状态，参见 [CAN接入实车任务清单.md](CAN接入实车任务清单.md)
  零、第一道/第二道闸门）。

- [ ] **0.3 确认 DBC 版本**
  沿用已验证过的 `vw_mqb.dbc`（[大众速腾CAN抓包解析报告.md](大众速腾CAN抓包解析报告.md)
  中三个候选 DBC 匹配度对比已确认 68% 最高，不需要重新做匹配度分析，除非车辆有
  改动怀疑平台不同）。

## 一、静止点火抓包复现（对照基线，确认这次环境依然一致）

- [ ] **1.1 车辆钥匙 ON，发动机不启动，静止**
  与之前抓包报告完全一致的场景，作为本次验证的时间对照基线。

- [ ] **1.2 用 cabana 抓包 60-120 秒**
  ```bash
  cabana --panda
  ```
  或如果 Orin NX 上跑：通过 `cereal/messaging/bridge <开发机IP>` 桥接后在开发机跑
  `cabana --zmq <ip>`（见 [远程调试指南.md](远程调试指南.md) 数据流调试部分）。
  抓包过程中**不做任何操作**（不转向、不挂挡、不踩刹车），保持基线状态。
  导出 CSV 到 `~/cabana_live_stream/`（cabana 默认行为）。

- [ ] **1.3 跑现有解析脚本，确认与历史报告结论一致**
  ```bash
  cd /home/wio/openpilot && source .venv/bin/activate
  CSV=~/cabana_live_stream/<刚才导出的csv>
  DBC=~/cabana_live_stream/vw_mqb.dbc  # 或本地 opendbc_repo 里的路径

  python3 tools/vw/can_analysis/check_carstate_deps.py "$CSV" "$DBC"
  python3 tools/vw/can_analysis/decode_can.py "$CSV" "$DBC"
  ```
  预期：`check_carstate_deps.py` 报告 17 个依赖消息全部命中（与历史报告一致）；
  `decode_can.py` 解析出的车速=0、档位=P，与静止点火状态吻合。
  **如果这一步就和历史结论不一致**（比如某个消息突然缺失），说明接入点/硬件/DBC
  版本发生了变化，需要先排查清楚才能继续，不要跳过这步直接做动态测试。

## 二、动态验证：方向盘（风险最低，钥匙 ON 即可测，不需启动发动机）

- [ ] **2.1 记录起始方向盘角度**
  方向盘打正（目视/物理居中），开始抓包。

- [ ] **2.2 缓慢向左打死方向盘，停留 3 秒，再缓慢回正，再向右打死，停留 3 秒，回正**
  全程持续抓包（建议单次抓包覆盖整个操作序列，30-60 秒）。

- [ ] **2.3 解析并交叉核对**
  ```bash
  python3 tools/vw/can_analysis/decode_can.py "$CSV" "$DBC"
  ```
  重点看 `decode_can.py` 输出里 `LWI_01`/`LH_EPS_03` 是否标注"有变化"（脚本对每个
  信号统计 min/max，取值不同会打印 `<-- 有变化`）。用 `--` 追加时间序列打印（如需
  更细粒度，可临时改脚本加 `print(t, dec['LWI_Lenkradwinkel'])` 逐帧看，或直接用
  `cabana` GUI 时序图观察波形）。

  验证标准（不是模糊的"看起来合理"，是具体可比对的）：
  - 左打方向盘时 `LWI_01.LWI_Lenkradwinkel` 应持续增大（或减小，取决于符号约定，
    但方向要与"回正→打死"过程单调一致）
  - 回正后应回到接近起始值（允许小误差）
  - 右打方向盘时应反向变化
  - `LH_EPS_03.EPS_Berechneter_LW`（EPS 计算转角）应与 `LWI_01` 同步变化、数值接近
    （历史报告记录过两者应该一致，是交叉校验关系）
  - 转向过程中 `LH_EPS_03.EPS_Lenkmoment`（转向力矩）应有明显波动（打方向盘时施加
    了真实力矩）

  **只有方向变化、幅度合理、两个信号源互相印证，才能确认方向盘角度信号映射正确**，
  不是"解析出一个数字就算过关"。

## 三、动态验证：挡位（如车辆支持钥匙 ON 挂挡，或需发动机启动）

- [ ] **3.1 确认挂挡是否需要发动机启动**
  DSG 自动挡部分车型钥匙 ON 即可挂挡（不启动发动机），部分需要启动。按实车情况
  确认，若需启动发动机则安排在相对安全的环境下做（比如挂 P/N/D/R 之间切换，脚踩
  刹车，车辆本身不会移动，但发动机运转，需要更留意周边环境和排烟通风）。

- [ ] **3.2 依次挂入 P → R → N → D → P，每个挡位停留 5 秒以上，全程抓包**

- [ ] **3.3 解析核对**
  ```bash
  python3 tools/vw/can_analysis/decode_can.py "$CSV" "$DBC"
  ```
  `Gateway_73.GE_Fahrstufe` 应依次显示 P/R/N/D/P，与实际挂挡操作严格一一对应
  （这是枚举值不是连续数值，验证更直接：挂什么挡就该显示什么，不允许有偏差）。

## 四、动态验证：刹车/油门踏板（发动机启动状态）

- [ ] **4.1 发动机启动，挂 P 挡，安全刹住**
  轻踩刹车踏板 2-3 秒后松开，重复 2-3 次，全程抓包。

- [ ] **4.2 解析核对**
  `ESP_05.ESP_Fahrer_bremst` 应在踩刹车时变为真（1），松开变回假（0），
  与踩踏节奏时间对应；`ESP_05.ESP_Bremsdruck`（制动压力）应在踩下时明显增大。
  `Motor_14.MO_Fahrer_bremst` 作为交叉校验，应与 `ESP_05` 同步。

- [ ] **4.3（可选）轻踩油门（挂 P/N 挡，确保车辆不会移动的前提下）**
  `Motor_20.MO_Fahrpedalrohwert_01` 应随踏板深度变化。

## 五、动态验证：车速（低速移动，封闭安全场地）

- [ ] **5.1 在封闭场地低速缓慢移动车辆**（挪车/倒车级别，不是开放道路）

- [ ] **5.2 解析核对**
  `ESP_19` 四轮速信号应从 0 变为非 0，且与实际移动方向/大致速度感觉吻合
  （不需要精确到 km/h 数值完全准确，重点是"从静止到有值"这个跃变确认信号活的）。
  同步观察 `ESP_21.ESP_v_Signal`（历史报告用这个作为车速主字段），确认两个车速
  来源互相印证。

## 六、汇总判定：能否拿到所需变量

对照 [第二阶段_接入CAN可行性评估.md](第二阶段_接入CAN可行性评估.md) 的"最小需求
表"，本清单验证通过后应能确认：

| 变量 | 对应验证步骤 | 判定标准 |
|------|------------|---------|
| 车速 `vEgo` | 五 | 从 0 到非 0 且方向合理 |
| 方向盘角度 | 二 | 双信号源同步、方向正确、能回正 |
| 档位 | 三 | 枚举值与实际挂挡严格对应 |
| 刹车状态 | 四 | 布尔值与踩踏节奏严格对应 |
| 油门 | 四（可选）| 随踏板深度变化 |

**只有以上全部打勾，才认为"CAN 数据解析验证通过、所需变量已确认能可靠抓到"**，
可以进入 [CAN接入实车任务清单.md](CAN接入实车任务清单.md) 里正式接入 openpilot
`card.py`/`carState` 的阶段（该清单里步骤 6/9/10/13 可视为本清单的简化重复，
因为已经在这里做过更严格的动态验证，openpilot 集成阶段主要复核软件层面读取的
`carState` 字段是否与这里独立解析的结果一致，而不必重新怀疑 DBC 信号映射本身）。
