# 速腾车道线预测 — 下一步开发路线

> 目标：在 24 款大众速腾（无 ACC）上实现车道线预测和行驶轨迹显示，不进行控车。

## 核心结论

**车道线预测完全不需要 CAN 数据。**

openpilot 的驾驶模型（`supercombo`）输入是摄像头图像 + 车速/方向盘角度（辅助输入），输出是车道线、Lead 车、行驶路径。车道线这部分是纯视觉的，CAN 只是锦上添花（提供更准确的车速给模型做速度感知优化）。

### 核心卡点分析

#### 卡点 1：modeld 无法自动启动（主要障碍）

**原因链**：
```
hardwared → onroad_conditions["ignition"] = False（无 panda 设备）
         → should_start = False
         → deviceState.started = False
manager  → modeld 启动条件 only_onroad(started=True) 不满足
         → modeld 不会被启动
```

`modeld` 的启动条件是 `only_onroad`，即 `started=True`。而 `started` 取决于 `hardwared` 检测到"点火"信号（ignition）。在 PC 无 panda 硬件环境下，ignition 永远是 False，所以 modeld 永远不会被 manager 自动拉起来。

#### 卡点 2：摄像头设备（次要）

当前系统无 `/dev/video*` 设备。需要接入 USB 摄像头，或用 `tools/webcam/demo.mp4` 修改 camera.py 做视频模拟。

### 解决方案

#### 方案 A：使用 `uiview.py` 模式（推荐快速验证）

项目自带 `selfdrive/debug/uiview.py`，它绕过 manager 直接启动进程并模拟点火状态：

```bash
cd /home/wio/openpilot
source .venv/bin/activate
export USE_WEBCAM=1

# 直接运行（会启动 webcamerad、modeld、UI 等进程并模拟 started=True）
python3 selfdrive/debug/uiview.py
```

原理：`uiview.py` 手动启动 `camerad/webcamerad`、`modeld`、`ui` 等进程，然后持续发送模拟的 `deviceState.started=True` 和 `pandaStates.ignitionLine=True` 消息，欺骗所有订阅方认为车辆已上路。

#### 方案 B：修改 manager 启动条件（长期方案）

在 `system/manager/manager.py` 中增加 PC 调试模式的强制 started 逻辑：

```python
# manager_thread() 主循环中，在获取 started 后增加：
started = sm['deviceState'].started
# PC调试模式：强制模拟上路状态
if os.getenv("FORCE_ONROAD"):
    started = True
```

然后启动时设置 `export FORCE_ONROAD=1`。

#### 方案 C：编写专用的 PC 调试脚本（推荐）

基于 `uiview.py` 改造，加入 webcamerad 支持：

```python
#!/usr/bin/env python3
"""PC 端车道线验证脚本 - 绕过 panda/ignition 限制"""
import time
from cereal import car, log, messaging
from openpilot.common.params import Params
from openpilot.system.manager.process_config import managed_processes
from openpilot.system.hardware import HARDWARE

if __name__ == "__main__":
    CP = car.CarParams(notCar=True, wheelbase=1, steerRatio=10)
    Params().put("CarParams", CP.to_bytes())
    Params().put_bool("IsDriverViewEnabled", True)

    # 启动流水线关键进程
    procs = ['webcamerad', 'modeld', 'ui', 'calibrationd', 'plannerd']
    for p in procs:
        managed_processes[p].start()

    # 模拟车辆上路状态
    pm = messaging.PubMaster(['controlsState', 'deviceState', 'pandaStates', 'carParams'])
    msgs = {s: messaging.new_message(s) for s in ['controlsState', 'deviceState', 'carParams']}
    msgs['deviceState'].deviceState.started = True
    msgs['deviceState'].deviceState.deviceType = HARDWARE.get_device_type()
    msgs['carParams'].carParams.openpilotLongitudinalControl = True
    msgs['pandaStates'] = messaging.new_message('pandaStates', 1)
    msgs['pandaStates'].pandaStates[0].ignitionLine = True
    msgs['pandaStates'].pandaStates[0].pandaType = log.PandaState.PandaType.uno

    try:
        while True:
            time.sleep(1 / 100)
            for s in msgs:
                pm.send(s, msgs[s])
    except KeyboardInterrupt:
        for p in procs:
            managed_processes[p].stop()
```

### 可能遇到的问题

| 问题 | 原因 | 解决方案 |
|------|------|---------|
| modeld 不启动 | started=False，无点火信号 | 使用 uiview.py 或方案 B/C 模拟 |
| webcamerad 不启动 | IsDriverViewEnabled=False | 运行 `python3 enable_camera.py` |
| webcamerad 报错 | 无 /dev/video0 | 接入 USB 摄像头或用 demo.mp4 |
| modeld 报 VisionIPC 错误 | webcamerad 没正常推流 | 先单独运行 webcamerad 确认输出 |
| 车道线无输出 | 图像格式不对（RGB vs YUV）| camera.py 已做 bgr→nv12 转换，正常 |
| UI 黑屏/无窗口 | X11 转发问题或无 GPU | 在有显示器的本机运行 |
| Raylib 初始化失败 | X11 转发延迟太高 | 需要在本地桌面环境运行 |

## 路线二：接入 CAN 数据（增强阶段）

### 目的

给 modeld 提供实际车速，使轨迹预测更准确。纯视觉下模型会用默认车速假设，接入 CAN 后能获得真实车速。

### 从抓包文件生成 DBC 的流程

#### 步骤 1：确认抓包格式

```bash
# rlog 格式
python3 -c "
import sys; sys.path.insert(0, '.')
from openpilot.tools.lib.logreader import LogReader
for msg in LogReader('your_capture.rlog'):
    if msg.which() == 'can':
        for frame in msg.can:
            print(f'src={frame.src} addr=0x{frame.address:03X} len={len(frame.dat)} dat={frame.dat.hex()}')
        break
"

# candump / csv 格式
head -50 your_capture.csv
```

#### 步骤 2：用 Cabana 加载已有 DBC 对比

```bash
# 启动 Cabana 可视化工具
python3 -m openpilot.tools.cabana.main
```

操作流程：
1. 加载抓包文件
2. 加载 `opendbc_repo/opendbc/dbc/vw_mqb_20.dbc`
3. 观察哪些 CAN ID 能正确解析（数值合理）
4. 标记解析异常的 ID（数值明显错误或全乱码）

#### 步骤 3：信号复用评估

速腾（MQB 平台）和 Golf MK7 的 CAN 信号对照：

| 信号类型 | CAN ID（参考） | 复用可能性 | 优先级 |
|---------|--------------|-----------|--------|
| 四轮转速 `Wheel_Speeds` | 0x0B2 | 几乎完全兼容 | ⭐ 高 — 车速来源 |
| 方向盘角度 `Steering_Angle` | 0x0C2 | 大概率兼容 | ⭐ 高 — 方向输入 |
| 油门踏板 | 0x???  | 兼容度高 | 低 — 不控车不需要 |
| 刹车踏板 | 0x???  | 兼容度高 | 低 — 不控车不需要 |
| ACC 相关 | N/A | 速腾无 ACC，忽略 | 无 |

#### 步骤 4：修正差异并生成速腾专用 DBC

```bash
# 基于 vw_mqb_20.dbc 创建速腾专用版本
cp opendbc_repo/opendbc/dbc/vw_mqb_20.dbc opendbc_repo/opendbc/dbc/vw_sagitar_2024.dbc
```

然后在 Cabana 中：
1. 逐一验证关键信号（车速、方向盘角度）
2. 对照实际数据调整 factor / offset / bit position
3. 保存为速腾专用 DBC
