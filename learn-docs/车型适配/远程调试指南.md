# Jetson Orin NX 远程调试指南

> 目标：在 Orin NX 装车/离线后，仍能从开发机远程连上去排查车道线预测问题
> （看日志、改启动脚本、跑 v4l2-ctl、实时看 modelV2 数据等）。

## 零、先理解三层结构

远程排查通常是三层的组合，从下往上：

| 层 | 作用 | 推荐方案 |
|----|------|---------|
| 网络可达 | 让 NAT/4G 后的 Orin 能被连到 | **Tailscale**（备选 cloudflared / ngrok / 同局域网）|
| 直接操作 | 在 Orin 上跑命令、改文件 | **Remote-SSH**（IDE 连过去，工具直接作用在 Orin）|
| 数据流调试 | 实时看 openpilot 消息 | **ZMQ bridge**（见 `ZMQ_MODE_GUIDE.md`）+ 日志拉取 |

Jetson 跑标准 Ubuntu/L4T（不像 comma3 的 AGNOS 那么锁），标准 SSH/工具链都能用。

安全底线：SSH 一律密钥登录、禁用密码；ZMQ 明文不加密，只在内网或加密隧道内用；
不要把端口裸暴露公网。

---

## 一、网络可达

### 方案 A：Tailscale（最推荐）

两端装完自动组一个加密内网，Orin 拿到固定 `100.x.x.x` 地址，直接 SSH。
零端口映射、自带加密、掉线自动重连。

Orin 端：
```bash
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up          # 首次会给一个登录链接，浏览器授权
tailscale ip -4            # 记下这个 100.x 地址
```

开发机端同样装 Tailscale 并登录同一账号，然后：
```bash
ssh <user>@<orin 的 100.x 地址>
```

### 方案 B：cloudflared 隧道（仓库已在用）

`容器发布.md` 里已有 `cloudflared service install <token>` 的用法，适合把某个服务
（SSH / UI）暴露成隧道。你已经熟，可复用；比 Tailscale 略绕。

### 方案 C：ngrok（临时一次性）

```bash
# Orin 端
ngrok tcp 22
# 开发机用 ngrok 给出的地址+端口 ssh
```
免费版地址每次会变，适合临时排查。

### 方案 D：同局域网

排查时 Orin 与开发机在同一 WiFi/有线网，直接内网 IP：
```bash
ssh <user>@192.168.x.x
```
无需任何隧道，最简单。

### 网络诊断（连不上时）
```bash
ping <ip>                       # 连通性
nc -vz <ip> 22                  # SSH 端口是否通
tailscale status                # Tailscale 各节点在线状态
```

## 二、直接操作：Remote-SSH

在 IDE（Kiro / VS Code）里用 **Remote-SSH** 连到 Orin，之后终端和文件操作直接
作用在 Orin 上——这是远程排查体验最接近本地的方式，也是让 AI 助手能直接在 Orin
上跑命令/改文件的前提。

### 1. 开发机生成并下发 SSH 密钥（一次性）
```bash
ssh-keygen -t ed25519 -C "orin-debug"           # 若还没有密钥
ssh-copy-id <user>@<orin_ip>                     # 把公钥装到 Orin
```

### 2. 写 SSH config（开发机 ~/.ssh/config）
```
Host orin
    HostName <orin 的 100.x 或内网 IP>
    User <user>
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
```
之后 `ssh orin` 即可。

### 3. Orin 端加固 sshd（可选但建议）
```bash
sudo sed -i 's/^#\?PasswordAuthentication.*/PasswordAuthentication no/' /etc/ssh/sshd_config
sudo systemctl restart ssh
```

### 4. IDE 连接
IDE 命令面板 → Remote-SSH: Connect to Host → 选 `orin`。连上后打开
`/home/<user>/openpilot`，即可远程编辑 `start_openpilot_orinnx.sh`、看日志、跑命令。

## 三、数据流调试

连上之后，除了直接看日志，还能实时看 openpilot 的消息流。

### 3.1 ZMQ bridge：在开发机实时看 Orin 的 modelV2

对应部署指南「确认 modeld 产出车道线」那步，但不必挤进 Orin 终端看。

Orin 端（把消息桥接到开发机）：
```bash
cd ~/openpilot
cereal/messaging/bridge <开发机IP>
```

开发机端（ZMQ 模式订阅）：
```bash
export ZMQ=1
python3 -c "
import cereal.messaging as messaging
sm = messaging.SubMaster(['modelV2'])
while True:
    sm.update(1000)
    if sm.updated['modelV2']:
        m = sm['modelV2']
        print('laneLineProbs:', [round(p,2) for p in m.laneLineProbs])
"
# 或用 PlotJuggler 图形化：
ZMQ=1 tools/plotjuggler/juggle.py --stream
```
细节与端口/防火墙见 `ZMQ_MODE_GUIDE.md`。**ZMQ 明文未加密**，务必走 Tailscale
隧道或仅限内网。

### 3.2 拉日志离线分析（不方便实时连时）

`start_openpilot_orinnx.sh` 里日志目录（参考主启动脚本约定）：
```bash
# 开发机把 Orin 的日志同步回来
rsync -avz orin:/data/logs/  ./orin_logs/          # SWAGLOG（系统日志）
rsync -avz orin:/tmp/data/   ./orin_realdata/      # OPENPILOT_DATA（本次运行数据）
```
拉回来后可离线定位 modeld/card/hardwared 的报错。

### 3.3 看进程与关键状态
```bash
# 在 Orin 上（或通过 ssh orin '...'）
tmux new -s op                      # 建议在 tmux 里跑，断线不丢
ps aux | grep -E "modeld|webcamerad|card|ui|hardwared"
v4l2-ctl --list-devices             # 确认摄像头设备号
```

## 四、推荐组合与首次排查流程

**推荐组合**：Tailscale 打通网络 → Remote-SSH 直接操作 → 需要看数据流时叠 ZMQ。

首次远程排查一条链路（对应部署指南第七节的风险点）：

1. `ssh orin`，确认能进。
2. 单摄先跑通：`SINGLE_CAM=1 ./start_openpilot_orinnx.sh`（规避双摄同步/带宽）。
3. 看是否卡在 onboarding：`grep -i "Startup blocked" /data/logs/*/`（脚本已自动写
   terms/training，正常不该再出现）。
4. 确认 `card` 写了 CarParams（否则 modeld 会阻塞）：
   ```bash
   ps aux | grep card
   python3 -c "from openpilot.common.params import Params; print(bool(Params().get('CarParams')))"
   ```
5. 用 3.1 的 ZMQ 订阅看 `laneLineProbs`，内侧两条 > 0.5 即链路通。
6. 通了再切双摄（去掉 `SINGLE_CAM=1`），观察是否刷 `frames out of sync`。
